# AI 营销助手业务规则（V1.0）

> 规则版本：`business-rules-v1.1.0`
> 适用范围：第一版 Demo；当前输入为 Mock 数据。
> 核心约束：事实与分数由代码生成，LLM 只能基于 Evidence Package 解释，不得修改分数或补造数据。

## 1. 确定性约束

- 相同的输入文件与相同规则版本必须生成相同 JSON。
- 所有时间计算使用数据中的 `interaction_snapshot_at` / `collected_at`，不读取系统当前时间。
- 所有列表按稳定 ID 排序；分数并列时按 ID 升序。
- 中间值使用完整精度，最终展示统一采用 `ROUND_HALF_UP` 保留两位小数。
- 缺失字段不填 0、不由 AI 猜测。Opportunity Score 对缺失维度移除权重并重新归一化，同时列入 `missing_information`。
- 未确认画像直接阻断；命中用户禁区的候选直接排除。
- 输出必须携带 `rule_version`、证据 ID、证据时间、正向因素、反向因素、缺失信息和置信度。

## 2. 热点规则

热点回答“当前内容在本批数据中有多热”，不等于市场需求，也不等于异常增长。

### 2.1 公式

各互动指标使用当前批次的稳定中位秩百分位（0–100），避免不同量级直接相加：

`Hotspot Score = 点赞百分位×20% + 收藏百分位×25% + 评论百分位×10% + 粉丝校正互动率百分位×15% + 新鲜度×10% + 插画相关度×20%`

- 粉丝校正互动率：`(点赞 + 收藏 + 评论) / max(作者粉丝数, 1)`。
- 新鲜度：`max(0, 100 × (1 - 发布天数 / 30))`，时间基准为该条记录的互动快照时间。
- 插画相关度：原始 0–1 数值乘以 100。

### 2.2 分层

- `hot`：分数 ≥ 70。
- `watch`：50 ≤ 分数 < 70。
- `normal`：分数 < 50。
- 插画相关度 < 0.50 时，即使总分高，也标记为 `mass_hot_low_relevance`，只能作为大众热点灵感，不能直接成为商业机会证据。

## 3. 异常增长规则

异常增长回答“同一内容在两个时间点之间是否突然加速”。至少需要同一 `post_id` 的两次快照；只有一次快照时返回 `insufficient_history`。

### 3.1 有效快照

- 使用最近两次快照。
- 间隔必须为 6–48 小时，否则返回 `invalid_interval`。
- 加权互动量：`点赞 + 收藏×2 + 评论×1.5`。
- 增长率：`(当前加权互动 - 上次加权互动) / max(上次加权互动, 100)`。
- 增长速度：`互动增量 / 间隔小时数`。

### 3.2 判定

同时满足下列条件才是 `abnormal_growth`：

1. 当前加权互动量 ≥ 500；
2. 增长率 ≥ 50%；
3. 增长速度 ≥ 100/小时；
4. 未触发可疑数据规则。

增长率 ≥ 500% 且评论占加权互动量 < 0.1% 时标记 `needs_review`，不能进入高置信机会推荐。

## 4. Opportunity Score

Opportunity Score 回答“某个具体市场候选与当前用户是否匹配”。每条市场橱窗为一个候选，LLM 不参与计算。

### 4.0 资格硬门槛

题材相似不能替代产品形态和创作媒介匹配。先通过硬门槛，再计算 Opportunity Score：

- 产品形态匹配分必须不低于 50；否则标记 `product_form_mismatch`，不计算最终机会分。
- 用户限制创作媒介时，市场候选必须提供 `medium`。缺失时标记 `medium_missing`，不得默认兼容；明确不同时标记 `medium_mismatch`。
- 例如“动物大头实体挂件”不等于“宠物拟人头像”；两者题材都可能包含宠物，但交付物、制作方式和购买动机不同。
- 不通过硬门槛的候选保留在审计结果中，`opportunity_score = null`、`recommendation_level = ineligible`，不能进入推荐排序。

| 维度 | 权重 | 计算口径 |
|---|---:|---|
| 画像匹配 | 25% | 接受业务与品类/标签匹配；品类命中 70 分，每个标签交集加 15 分，上限 100 |
| 产能匹配 | 15% | `min(100, 每周产能 / 品类标准工时 × 100)` |
| 价格匹配 | 15% | 用户与市场价格区间的交集/并集；无交集时按区间距离衰减 |
| 需求信号 | 15% | 销量和收藏各占一半，分别按 40 单、80 收藏封顶 |
| 竞争吸引力 | 10% | `100 × (1 - min(同类数量/30, 1))` |
| 趋势相关度 | 15% | 同品类/标签匹配热点的最高分 × 插画相关度；无匹配为 0 |
| 证据完整度 | 5% | 市场六个 P0 字段的非空比例 |

最终分数为各有效维度加权和；若某维度缺失，则删除该维度并对剩余权重归一化。这样不会把“缺数据”误当成“表现差”，但会降低置信度。

### 4.1 推荐等级与置信度

- `recommended`：≥ 75；`test`：60–74.99；`observe`：40–59.99；否则 `not_recommended`。
- 证据完整度 ≥ 85 为高置信，65–84.99 为中置信，否则为低置信。
- 推荐等级表示计算结果，不代表承诺曝光、咨询或成交。

## 5. Evidence Package 输出

每个候选必须返回：候选 ID、总分、各维度分、实际使用权重、市场证据 ID、趋势证据 ID、证据时间、正向因素、反向因素、缺失信息、置信度和规则版本。后续 AI 只读取这组字段生成自然语言解释。

## 6. 当前数据缺口

- `trends.json` 当前每条内容只有一次互动快照，只能计算热点，不能判断异常增长。
- 真实上线前需为同一 `post_id` 连续采集至少两次，且保留原始累计值与快照时间。
- 当前品类标准工时、销量/收藏封顶值和竞争数量上限均为 Demo 假设，必须通过访谈和真实样本校准。

## 7. 运行与验收

```bash
source .venv/bin/activate
python scripts/run_scoring.py --profile-id USR-001 --output mock_data/scoring_usr001.json
python -m unittest discover -s tests -v
```

验收要求：重复执行输出字节一致；打乱输入顺序结果不变；未确认画像被阻断；单快照不产生异常增长结论；阈值边界符合定义。
